# Инструментальные среды разработки и сопровождения программных средств

Подтверждённая тема открытого лабораторного занятия: бизнес-моделирование; графические, имитационные, исполняемые, функциональные, поведенческие и информационные модели; Flow Chart, DFD, RAD, IDEF и UML.

- [Мастерская](https://zholdaskali.github.io/vm-quest/business/)
- [Пульт](https://zholdaskali.github.io/vm-quest/teacher.html)
- [Презентация и план](https://zholdaskali.github.io/vm-quest/materials/)
- [Приглашение](https://zholdaskali.github.io/vm-quest/materials/business-invitation.html)

Шесть этапов моделируют обслуживание заявки о неисправном компьютере. Результат — модели, роли, IDEF0 и эксперимент с длительностями. Числа условные: одна заявка без очередей. Пошаговый интерпретатор учебный, не промышленный BPM-движок. RAD показан в упрощённом виде дорожек ответственности.

Тестовый код: **W358J48E**. Для занятия создать новую группу типа «Бизнес-моделирование · инструментальные среды». Секрет преподавателя прежний; результаты обновляются каждые 3 секунды.

Прежняя снятая тема удалена из публичного интерфейса и материалов. Её исторические строки в БД не удаляются и не переоцениваются; старые входы получают сообщение о снятии темы. Старые групповые коды не переводятся в новый квест автоматически. Дополнительная VM-практика остаётся отдельной страницей vm.html.

Сервер выбирает проверяющий движок по kind состояния (business или VM), браузер не передаёт готовые баллы. Таблицы закрыты RLS от прямого клиентского доступа. Секреты и токены не входят в репозиторий.

Проверки: `node tests/business.cjs`; затем браузерные и реальные API-проверки отдельно.

Методические источники указаны в плане занятия: OMG, NIST, IBM и официальная документация инструментов.
